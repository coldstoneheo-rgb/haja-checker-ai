> 작성 2026-11-27 (HO-2026-1127). 값(주소·키·ID)은 이 문서에 적지 않습니다. 이 레포는 PUBLIC입니다.

## 0. 이번 판에서 되는 것과 아직 스텁인 것

| 구분 | 항목 | 이번 판 동작 | 이번 시험의 목적 |
|---|---|---|---|
| **동작** | 세션·체크리스트·하자 등록·보고서 미리보기 | 실제 동작 | 화면이 실기기에서 깨지지 않는지 본다 |
| **동작** | 사진 | 웹 `<input type=file capture>` | 토스 WebView에서 촬영·앨범이 되는지 **먼저** 실측한다 |
| **동작** | AI 분석 | 배포 주소 + CORS(PR #25) | 토스 출처에서 200이 오는지 본다. 실기기 Origin 값도 읽는다 |
| 스텁 | 광고(전면·리워드) · 식별키(로컬 폴백) · 보고서 저장·공유 · 외부 링크(openURL) | SDK 호출 없음. 버튼을 누르면 «이 기능은 곧 지원됩니다.»가 나온다 | 눌러도 앱이 멈추지 않는지만 본다. SDK 연결은 다음 조각에서 한다(아래 «결정 대기» ①) |

## 1. 준비물
- 휴대폰: 토스앱 로그인 · **만 19세 이상** · **워크스페이스 멤버** 계정(QR 실행 조건 3개, console-workspace.md)
- PC: 이 레포 main 최신 · Node 20+ · `npm ci` 완료
- 콘솔: 앱인토스 워크스페이스 접근 · 미니앱 `haja-check` 등록(appName이 `apps-in-toss.config.ts`와 같아야 함)
- 배포: Vercel의 하자체크 웹 주소(https). AI 분석을 볼 때만 필요하다

## 3. 카메라 권한 사유 초안 (콘솔에 입력란이 있으면 그대로 붙여 넣기)
- **camera**: «하자 점검 중 벽·바닥·창호 등 하자 부위를 직접 촬영해 점검 기록과 보고서에 첨부하기 위해 카메라를 사용합니다.»
- **photos(읽기)**: «이미 찍어 둔 하자 사진을 앨범에서 골라 점검 기록에 첨부하기 위해 사진 보관함을 읽습니다.»
- (짧은 판, 40자 이내 제한이 있으면) «하자 부위 사진을 촬영해 점검 기록에 첨부합니다.» / «앨범의 하자 사진을 골라 점검 기록에 첨부합니다.»

## 4. 결정 대기 (사용자)
1. **SDK 연결을 QR 시험 전에 넣을까?** 지금 판은 광고·식별키·저장·공유·openURL이 스텁입니다. 그래서 이번 QR은 «화면 + 카메라 input + AI 분석 + Origin»만 확인합니다. SDK를 연결한 판을 한 번 더 만들면 QR을 한 번 더 열어야 합니다. **권고**: 이번 QR로 카메라 input과 Origin을 먼저 확인합니다. 그 결과를 받아 SDK 연결 PR을 만들고, 2차 QR을 엽니다. 카메라 input이 안 되면 `Device.openCamera`를 같은 PR에 넣습니다.
2. **PR #25 머지·배포**: 머지하면 웹 주소에서는 다른 사이트 출처의 POST가 403이 됩니다(같은 출처 화면은 그대로). 이것이 AI 분석 QR의 전제입니다.
3. **Origin이 기본값과 다를 때**(D2): Vercel env `HAJA_CORS_ORIGINS`에 D2 값을 넣고 재배포합니다. 쉼표로 여러 개를 넣을 수 있습니다. `*`는 받지 않습니다.

## 5. 끝난 뒤 정리 (선택, 2분)
- `toss/.env.local`은 남겨 둬도 됩니다(커밋 안 됨). 주소가 바뀌면 P2부터 다시 합니다.
- QR판 데이터는 출시판과 공유되지 않습니다(storage.md). 시험 세션은 지워도 되고 남겨도 됩니다.
